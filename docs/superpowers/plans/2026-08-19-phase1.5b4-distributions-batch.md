## Constraints that bite (read before authoring anything)

1. **`erf`/`normalCdf` built as `0.5*(1+erf(z))` loses precision at extreme `|z|`, and this is a property of the formula, not of any particular implementation.** Measured: even with an internally-precise standard-normal CDF, routing it through `2*Φ(z√2)-1` and back through `0.5*(1+erf)` starts exceeding `verify.py`'s `1e-9` relative bound once the *standard normal z-score* passes about **6** (measured relative error 1.26e-10 at z=-6, 4.8e-7 at z=-6.5 — the crossing happens inside that half-unit). This is unavoidable: a value within `2e-16` of ±1 cannot encode a tail probability tinier than that, no matter how the ±1-valued function is computed. **It does not matter for this batch** — §3's floor already keeps every *answer* within roughly `z ∈ [-2.4, 2.4]`, and no template needs an intermediate z beyond about 4 — but do not widen a Normal template's parameter range without rechecking this, and do not "fix" it by trying to make `erf` itself more precise; the cancellation happens one level up, in the composition.

2. **The internal series/continued-fraction split inside `normalCdf` has its own crossover to get right, and picking it wrong reintroduces the same failure mode one step earlier.** The commonly-cited Marsaglia (2004) algorithm switches from a power series to a continued fraction at `|x| = 7`; **do not use that threshold.** Measured: the power series alone loses accuracy as `|x|` approaches its crossover from below (relative error 8e-10 at `|x|=5`, 7.9e-7 at `|x|=6`, 5.2e-4 at `|x|=7`), while the continued fraction is uniformly excellent from `|x| ≈ 2` outward but **divides by zero at `x = 0`** and must not be used there. Task 1's implementation crosses over at `|x| = 4`, where both branches independently measure under `1e-11` — see Task 1 Step 3 for the measured table. If this module is ever touched again, re-measure before moving the threshold; it is not a knob to nudge on intuition.

3. **Small probabilities are this batch's version of B3's near-zero-EV hazard.** `grade.ts`'s bound is `rel · |expected|`, so it shrinks toward strict float equality as the answer approaches zero, and a PMF/CDF value can be manufactured near zero trivially — `P(X=20)` for `Poisson(λ=2)` is `~1e-14`, not a typo. **`constraint: (p) => answerOf(p) >= 0.01` on every legal draw, same floor B3 used, now guarding a small-probability collapse instead of a near-zero expectation.** The ceiling (`<= 1e4`) is inherited for free — no answer in this batch plausibly exceeds it. Extract the answer formula into a module-local helper (e.g. `pmfOf`) and call it from both `constraint` and `derived`, exactly as B3's `evOf` pattern — `constraint` never sees `derived` (`packages/engine/src/problem.ts:24`). **This floor is `montecarlo`-method problems' STARTING point, not their final one — see constraint 10.**

4. **`emit.ts:46` floors every `params`/`derived` value at `1e-6`, independently of the answer floor above.** Do not put a raw PMF term, a truncation-tail mass, or any other sub-`1e-6` quantity into `derived` even when it is not the answer. In particular, an unbounded family's truncation-tail bound (constraint 6 below) must never itself be stored in `derived` — only the enumeration *cap* (an integer) belongs there. **This bit the exemplar itself** — see Task 1 Step 10's note on dropping `qToN`.

5. **Tolerance is `{ rel: 0.005 }` on all 25. Never `abs`, never `abs: 0`.** Identical reasoning to B3: `emit.ts:43`'s `abs` gate must hold for the *smallest* `|answer|` across all 100 emitted draws, which requires enumerating the draw space to pick safely, and `registry.test.ts` pins the corpus's `abs: 0` count at exactly counting's 15.

6. **Unbounded discrete families (Poisson, geometric, negative binomial) need a truncation point whose tail is provably `< 1e-12`.** `verify.py:52` compares brute-force output **unscaled** at `1e-9` for the `brute-force` method — the same rule B3's payoff cap exists to satisfy, applied to a truncation point instead of a payoff magnitude. Declare the cap as a `derived` integer (contract item 4) so the TS reasoning and the Python truncated-sum check are inspectable against the same number.

7. **Distinctness is measured, not assumed — and the CI gate does not know about "saturation."** `draw-space.test.ts`'s committed test asserts `distinctAtBand(legalAnswers(t)) >= 12` as a **hard floor with no exception**. That file's own `neighbourDensity().saturated` flag exists to tell a *human* when a low full-space count is an artefact of a dense, transitively-overlapping range rather than a real collapse (see B3's own commentary on `sum-of-bets-variance`) — but the committed assertion in `draw-space.test.ts` does not read that flag and will fail regardless of whether the collapse is "real" or an artefact of saturation. **Measured directly on this batch's own exemplar:** restricting `binomial-exact-count`'s `k` to `1..16` (to simplify one candidate Sanity-check design) dropped the full-space distinct-answer count from 26 to **8** — below the floor — purely from losing one slice of a saturated space, even though the *texts-per-100* signal barely moved (99 either way). The fix was not "the check is wrong, ignore it" — it was redesigning the Sanity check to work at `k=0` too, so the full `k ∈ 0..16` range could stay. Enumerate with the real formula before committing a parameter range; do not reason about saturation as a way to justify skipping the floor.

8. **`prose-claims.test.ts` requires ≥3 claims per template, and its lookup was hardcoded to one topic.** Beyond the three gate files the spec's own review already named (§7 items 6–8), a fourth spot the spec review did not catch: `content/problems/prose-claims.test.ts:581` defines `templateFor = (slug) => PROBLEMS.find(t => t.id === \`ev-variance/${slug}\`)`, and its closing coverage test (`content/problems/prose-claims.test.ts:642`) compares `Object.keys(CLAIMS)` only against `probability/ev-variance` problem ids. Both are hardcoded to one topic the same way `printed-precision.test.ts`'s `TOPICS` array and `draw-space.test.ts`'s `TOPIC` constant were. **Task 1 fixes `draw-space.test.ts` and `prose-claims.test.ts`** — the latter migrating `CLAIMS` from bare-slug keys to full `t.id` keys so a slug collision between topics can never silently shadow a claim (see Task 1 Step 7). **`printed-precision.test.ts`'s `TOPICS` array does NOT get fixed until Task 2** — see constraint 9.

9. **`printed-precision.test.ts` enforces a per-topic minimum chain count, not just membership in `TOPICS`.** `content/problems/printed-precision.test.ts:15` sets `MIN_CHECKED_PER_TOPIC = 1000` and asserts `audit.checked > MIN_CHECKED_PER_TOPIC` per topic (line 40) — a topic newly added to `TOPICS` with too few problems **fails immediately**, not silently. One problem (Task 1's exemplar) × 200 seeds × ~4 evaluable `$…=…$` chains per instance is ~800 — under the floor, regardless of what order Task 1's own steps run in. **`"probability/distributions"` is added to `TOPICS` in Task 2, once 8 problems exist** (comfortably over 1000 even at 4 chains/instance) — not in Task 1 alongside the single exemplar.

10. **Monte Carlo problems need a materially higher answer floor than the batch's shared 0.01 from constraint 3 — compute it from `verify.py`'s noise bound, don't inherit the global floor.** `verify.py:44` requires `3·se <= bound/2` with `bound = rel·|answer| = 0.005·|answer|`. For a Bernoulli-style probability estimate, `se ≈ sqrt(p(1-p)/N)`, so the requirement works out to roughly `N >= 1.44e6/p` (from `se <= 0.000833p` ⇒ `N >= p(1-p)/(0.000833p)² ≈ 1/(6.94e-7·p)`). At the batch's global floor `p=0.01` that is **~144 million trials per instance** — impractical in both runtime and the ~1GB an unvectorized draw of that size costs. **Task 4's and Task 5's `montecarlo`-method problems use an answer floor of 0.1, not 0.01** — `N ≈ 1.44e7` at that floor, comfortably fast and light in vectorized numpy (well under a second, well under 200MB transient). The `brute-force`-method problems in this batch (everything through Task 3, plus Task 4's two discrete-uniform problems) keep the global `0.01` floor from constraint 3 unchanged — only the Monte Carlo noise bound, not the emit-time answer-shape check, forces this relaxation.

- [x] **Step 3: Implement `erf.ts`**

Create `packages/engine/src/erf.ts`:

```ts
// Standard normal PDF/CDF via Marsaglia (2004)'s series/continued-fraction hybrid, and the
// quantile via Acklam's rational approximation refined by one Newton step. Coefficients and
// crossover points below are pinned from measurement (see this file's own test and the plan
// this shipped from), not from the commonly-cited |x|=7 crossover — that one is unsafe: the
// series loses accuracy approaching it from below (measured relerr 7.9e-7 at |x|=6), while the
// continued fraction is excellent from |x|~2 outward but divides by zero at x=0.

function stdNormalPdf(x: number): number {
  return Math.exp((-x * x) / 2) / Math.sqrt(2 * Math.PI);
}

// |x| < 4: power series. |x| >= 4: continued fraction for the tail. Both branches measure
// under 1e-11 relative error at the x=4 crossover itself — see erf.test.ts for the pinned
// values this is checked against.
function stdNormalCdf(x: number): number {
  if (Math.abs(x) < 4) {
    let s = x, t = 0, b = x, i = 1;
    while (s !== t) {
      t = s;
      b *= (x * x) / (2 * i + 1);
      s += b;
      i++;
    }
    return 0.5 + s * Math.exp((-x * x) / 2 - 0.5 * Math.log(2 * Math.PI));
  }
  let c = 0;
  for (let i = 60; i >= 1; i--) c = i / (Math.abs(x) + c);
  const tail = Math.exp((-x * x) / 2 - 0.5 * Math.log(2 * Math.PI)) / (Math.abs(x) + c);
  return x < 0 ? tail : 1 - tail;
}

export function erf(x: number): number {
  return 2 * stdNormalCdf(x * Math.SQRT2) - 1;
}

export function normalCdf(x: number, mu = 0, sigma = 1): number {
  return 0.5 * (1 + erf((x - mu) / (sigma * Math.SQRT2)));
}

// Acklam's rational approximation, ~1.15e-9 accurate on its own; the coefficients are the
// standard published ones. Refined by one Newton step against stdNormalCdf/stdNormalPdf —
// measured round-trip error normalQuantile(normalCdf(x)) over x in [-4,4]: max 8.9e-12.
const A = [-3.969683028665376e1, 2.209460984245205e2, -2.759285104469687e2, 1.38357751867269e2, -3.066479806614716e1, 2.506628277459239];
const B = [-5.447609879822406e1, 1.615858368580409e2, -1.556989798598866e2, 6.680131188771972e1, -1.328068155288572e1];
const C = [-7.784894002430293e-3, -3.223964580411365e-1, -2.400758277161838, -2.549732539343734, 4.374664141464968, 2.938163982698783];
const D = [7.784695709041462e-3, 3.224671290700398e-1, 2.445134137142996, 3.754408661907416];
const P_LOW = 0.02425;
const P_HIGH = 1 - P_LOW;

function acklam(p: number): number {
  if (p < P_LOW) {
    const q = Math.sqrt(-2 * Math.log(p));
    return (((((C[0] * q + C[1]) * q + C[2]) * q + C[3]) * q + C[4]) * q + C[5]) /
      ((((D[0] * q + D[1]) * q + D[2]) * q + D[3]) * q + 1);
  }
  if (p <= P_HIGH) {
    const q = p - 0.5, r = q * q;
    return ((((((A[0] * r + A[1]) * r + A[2]) * r + A[3]) * r + A[4]) * r + A[5]) * q) /
      (((((B[0] * r + B[1]) * r + B[2]) * r + B[3]) * r + B[4]) * r + 1);
  }
  const q = Math.sqrt(-2 * Math.log(1 - p));
  return -(((((C[0] * q + C[1]) * q + C[2]) * q + C[3]) * q + C[4]) * q + C[5]) /
    ((((D[0] * q + D[1]) * q + D[2]) * q + D[3]) * q + 1);
}

export function normalQuantile(p: number, mu = 0, sigma = 1): number {
  const x0 = acklam(p);
  const x = x0 - (stdNormalCdf(x0) - p) / stdNormalPdf(x0);
  return mu + sigma * x;
}
```

```ts
import type { Params, ProblemTemplate } from "@qp/engine";
import { fmtNum } from "../util";

// C(n,k) via the standard multiplicative recurrence — kept module-local; no problem module
// shares code with another (file structure table).
function comb(n: number, k: number): number {
  if (k < 0 || k > n) return 0;
  const kk = Math.min(k, n - k);
  let r = 1;
  for (let i = 0; i < kk; i++) r = (r * (n - i)) / (i + 1);
  return r;
}

  comb(p.n, p.k) * (p.failPct / 100) ** p.k * (1 - p.failPct / 100) ** (p.n - p.k);
```

```python
"""Independent Python counterparts for content/problems/distributions/*.
exact(): re-derives every TS `derived` value in plain float arithmetic (double-entry) — MEANT
to mirror the template, in floats, same convention as bayes/counting/ev_variance.
brute()/simulate(): recompute the ANSWER by an independent path per spec §5's table, never by
re-calling the template's closed form."""

import itertools
from math import comb


def binomial_exact_count_exact(p):
    n, k, fail_pct = int(p["n"]), int(p["k"]), p["failPct"]
    prob = fail_pct / 100
    q = 1 - prob
    comb_nk = comb(n, k)
    n_minus_k = n - k
    pmf = comb_nk * prob**k * q**n_minus_k
    # q_to_n stays local, same reason as the TS side — never enters the returned dict, which
    # must mirror TS `derived` exactly (verify.py compares key-for-key).
    q_to_n = q**n
    at_least_one = 1 - q_to_n
    return {
        "prob": prob, "q": q, "combNK": comb_nk, "nMinusK": n_minus_k,
        "pmf": pmf, "atLeastOne": at_least_one,
    }


def binomial_exact_count_brute(p):
    """Enumerate all 2^n binary outcome sequences directly and sum the probability of every
    sequence with exactly k ones — never calls comb(), which is what makes this independent
    of the template's own C(n,k) shortcut."""
    n, k = int(p["n"]), int(p["k"])
    prob = p["failPct"] / 100
    total = 0.0
    for seq in itertools.product((0, 1), repeat=n):
        if sum(seq) == k:
            total += prob**k * (1 - prob) ** (n - k)
    return total


SOLVERS = {
    "distributions/binomial-exact-count": {"exact": binomial_exact_count_exact, "brute": binomial_exact_count_brute},
}
```
