## Non-negotiables

**All of B14's items 0-8, B15's two additions, B16's A-D and B17's restatement apply unchanged** —
see `2026-08-24-phase1.5b17-inference-batch.md`. The ones this batch leans on hardest:

- **Probe before prose** — done; the roster below is measured. **Re-probe under the real id** when a
  template is registered (`npx tsx tools/probe.ts statistics/<slug>`), because `emittedSpread` seeds
  from an FNV hash of the id and `maxRepeat` re-rolls. A stub that measured `maxRepeat 3` can land
  at 4, and 4 is the ceiling.
- **The LaTeX allowlist is CLOSED.** `RECOGNISED_CMD` (`content/problems/printed-precision.ts:93`)
  is exactly: `dfrac frac binom sqrt times cdots left right mid text bar cap max geq sigma lambda
  mu \,`. **`\hat` is NOT in it** — this batch is about fitted values, so the temptation is
  constant. Write the fitted value as a plain letter `f`, never `\hat{y}`. **`\sum` is NOT in it** —
  write centred sums as `S_{xy}`, `S_{xx}` and raw ones as `T_{xy}`, `T_{xx}`, plain Latin letters
  with subscripts, defining them in prose. `\bar{x}` and `\bar{y}` are fine (`bar` is recognised).
  Coefficients are `b`, `c`, `g` — never `\beta`, `\alpha`, `\delta`.
- **Every symbolic side needs a plain Latin letter outside any macro.**
- **Never re-use a rounded rendering as an operand.** A root or a power of exact literals is written
  as ONE chain and the result is a label from then on. **This plan's own sketches violate that rule
  in at least two places** — #3's sanity-check root (caught in Task 1, would have failed 36 of 290
  draws) and #10's (fixed in Task 4's step). Where a sketch below prints `\sqrt{label}`, root the
  exact integers instead. **The non-negotiable beats the sketch every time**; a template that
  follows a sketch into a rounded operand is wrong even though the sketch said so.
- **A negative operand needs its own parentheses** (`(-3)^{2}`, `4\times(-2)`); prose interpolates
  `fmtNum(v)`, never a typed minus — emit's tokenizer is sign-blind. This batch draws negative
  slopes, deviations and residuals, so it bites in #1, #5, #7, #11 and #12.
- **Subscripts and exponents are numbers to the emit tokenizer**: the `2` in `x^{2}`, the `2` in
  `n-2`, the `1` in `1-R^{2}` all go in `constants`.
- **A module-level helper is licensed only if `constraint` reaches it.**
- **Claims travel with the template.** Each task's claims step is not optional — the coverage test
  fails without it. ≥ 3 per template, each with a `breaks` that a 2% answer error trips, at least
  one reading `d.answer` itself.
- **Answers are computed from exact operands, never from a rounded label** (B17's precision hole).
  Round only at the ninth decimal, and only for display-bound derived keys.

### Decided for this batch (from the spec)

- **Every invariance template asks for the transformed quantity, never the invariant ratio.** A
  ratio answers the same number on every seed: it cannot clear the 12-distinct floor and it makes
  the mutation check vacuous, because a broken answer expression still returns the constant. This
  governs #4, #5 and #11 — the question is always "what is the new slope / intercept", never "by
  what factor did it change".
- **#3 ships as the ratio.** The inversion fallback (ask for RSS) is NOT needed; measured 83
  distinct at band.
- **#9 is one variable over two periods**, so `sx = sy` and the slope is `r` itself. It must not
  recompute `r·sy/sx` — that is the existing d2 `regression-slope-from-moments`.
- **No `version` bumps anywhere in this batch.** A changed question needs one; a changed topic does
  not, and Task 6 changes only topics.

```ts
// content/problems/statistics/fitted-value-and-residual.ts
import type { ProblemTemplate } from "@qp/engine";
import { fmtNum } from "../util";

// The residual is the answer and it is NOT a drawn axis: y0 is drawn independently of the line and
// `constraint` keeps the gap in a readable band, so the answer is signed and spread rather than
// readable off the statement. The slope steps in halves and x0 is an integer, so the fitted value
// is exact on every draw and the subtraction that produces the answer has no rounded operand.
export const fittedValueAndResidual: ProblemTemplate = {
  id: "statistics/fitted-value-and-residual",
  version: 1,
  topic: "statistics/estimation",
  difficulty: 1,
  firms: [{ firm: "two-sigma", weight: 0.25 }, { firm: "de-shaw", weight: 0.2 }, { firm: "citadel", weight: 0.15 }],
  source: { kind: "textbook", inspiration: "the residual as the observed value less the fitted one" },
  params: {
    a: { choices: [-8, -5, -2, 3, 6, 10, 12, 15] },
    b: { range: { min: 0.5, max: 3, step: 0.5 } },
    x0: { choices: [4, 6, 7, 9, 11, 12, 14, 16] },
    y0: { choices: [10, 14, 18, 22, 26, 30, 34, 38, 42] },
  },
  constraint: (p) => {
    const r = p.y0 - (p.a + p.b * p.x0);
    return Math.abs(r) >= 1.5 && Math.abs(r) <= 14;
  },
  derived: (p) => {
    const round = (x: number) => Math.round(x * 1e9) / 1e9;
    const slopeTerm = round(p.b * p.x0);
    const fitted = round(p.a + p.b * p.x0);
    return {
      slopeTerm,
      fitted,
      above: p.y0 > fitted ? 1 : 0,
      answer: round(p.y0 - (p.a + p.b * p.x0)),   // from the exact operands, not from `fitted`
    };
  },
  answerKey: "answer",
  accepted: { tolerance: { rel: 0.005 } },
  statement: (p) =>
    `A desk fits a least-squares line predicting a stock's daily volume in thousands of shares from the number of news items about it that morning. The fitted line has intercept ${fmtNum(p.a)} and slope ${fmtNum(p.b)}. ` +
    `On a day with ${fmtNum(p.x0)} news items the volume actually came in at ${fmtNum(p.y0)} thousand shares. What is that day's residual?`,
  solution: (p, d) => [
    // Claim-free segment (non-negotiable 6): symbolic only, no printed operands.
    { title: "A residual is what the line missed by", body: `The fitted line gives a prediction $f=a+bx$ at each value of the predictor. The residual is the observed value less that prediction, $e=y-f$. It is not the error term of the model: the error is the distance from the true line, which nobody observes, while the residual is the distance from the line that was actually fitted to this sample.` },
    { title: "The prediction on the day", body: `At ${fmtNum(p.x0)} news items the slope contributes $${fmtNum(p.b)}\\times${fmtNum(p.x0)}=${fmtNum(d.slopeTerm)}$, and adding the intercept gives a prediction of $${fmtNum(p.a)}+${fmtNum(d.slopeTerm)}=${fmtNum(d.fitted)}$ thousand shares.` },
    { title: "Answer", body: `The observed volume was ${fmtNum(p.y0)}, so the residual is $${fmtNum(p.y0)}-${fmtNum(d.fitted)}=${fmtNum(d.answer)}$ thousand shares. The sign matters: it says the day came in ${d.above ? "above" : "below"} what the line predicted.` },
    { title: "Sanity check", body: `Residuals from a fitted line with an intercept sum to zero across the whole sample, so a single one of ${fmtNum(d.answer)} says nothing on its own about whether the line is any good — only that this day sat that far off it. A day exactly on the line would have a residual of 0.` },
  ],
  keyInsight: "A residual is a distance from the line that was fitted, not from the true relationship, and the two are different objects: one is observed, the other never is. Least squares chooses the line that makes the squared residuals as small as possible, which is why they carry the sign of the miss and sum to zero.",
  commonTrap: "Subtracting the other way round and reporting the prediction less the observation, which flips the sign of every residual. The deeper slip is calling the residual the error — the error is measured from the unobservable true line.",
  expectedPaceS: 45,
  verify: { method: "brute-force" },
  constants: [0],
};
```

- [ ] **Step 2: Write #2 `regression-intercept-from-means`.** Statement: a fitted line predicts a

      chain and label it. `constants: [1, 2]` (the `1` in `1-R/T`, the exponent in `R^{2}`).

- [ ] **Step 1: #4 `slope-after-rescaling-x`.** Statement: a slope is quoted per old unit of the
      predictor (say per dollar of notional, or per basis point); the desk re-expresses the
      predictor in units `k` times smaller and the response in units `ybarScale` times larger; what
      is the slope in the new units? Params as the stub: `b` range `1.2..9.6` step `0.4`, `k`
      `[4,5,8,10,12,16,20,25,40,50]`, `ybarScale` `[1,2,5]`. Derived: `numer` = `b*ybarScale`,
      `answer` = `(b*ybarScale)/k` from exact operands. **Asked as the new slope, never the factor**
      — the factor is constant across seeds. Claim-free: a slope carries units of response per unit
      of predictor, so multiplying the response by `c` multiplies it and dividing the predictor by
      `k` divides it: $b'=\dfrac{cb}{k}$. Printed chains: $${ybarScale}\times${b}=${numer}$ then
      $\dfrac{${numer}}{${k}}=${answer}$. Sanity check: the correlation and R² are unchanged by any
      rescaling of either variable — only the slope moves, because only the slope carries units.
      `constants: []`.

- [ ] **Step 2: #5 `intercept-after-shifting-x`.** Statement: a line has intercept `a` and slope
      `b`; the predictor is re-expressed as its distance from `c` (years since `c`, or degrees above
      `c`); what is the new intercept? Params as the stub: `a` `[-20,-12,-6,4,9,14,22,30]`, `b`
      range `0.6..3.4` step `0.2`, `c` `[5,8,10,12,15,18,20,25,30]`. Derived: `shiftTerm` = `b*c`,
      `answer` = `a + b*c`. **Negative `a` prints through `fmtNum`, never as a typed minus.**
      Claim-free: substituting $x=x'+c$ into $y=a+bx$ gives $y=(a+bc)+bx'$, so the slope is
      untouched and the intercept absorbs $bc$. Printed chains: $${b}\times${c}=${shiftTerm}$ then
      $${a}+${shiftTerm}=${answer}$. Sanity check: centring the predictor at its own mean is this
      operation with `c` set to $\bar{x}$, which makes the intercept equal $\bar{y}$ — the usual
      reason to do it. `constants: []`.

- [ ] **Step 3: #6 `slope-through-the-origin`.** Statement: a hedge ratio is fitted with the
      intercept forced to zero over `n` observations, with raw sums `sumXY` and `sumX2` given; what
      is the slope? Params as the stub: `sumXY`
      `[180,240,300,360,420,480,560,640,720,840,960]`, `sumX2` `[120,160,200,240,320,400,480,600]`,
      `n` `[8,10,12,15,20]`, `constraint` keeping the slope in `[0.4, 5]`. Derived: `answer` =
      `sumXY/sumX2`, exactly rational. **`\sum` is not in the allowlist** — write the raw sums as
      `T_{xy}` and `T_{xx}`, plain letters with subscripts, defined in prose as the uncentred sums.
      Claim-free: with no intercept the normal equation is $bT_{xx}=T_{xy}$, so
      $b=\dfrac{T_{xy}}{T_{xx}}$ — uncentred, because there is no mean to subtract when the line is
      pinned at the origin. Printed chain: $\dfrac{${sumXY}}{${sumX2}}=${answer}$. Sanity check: with
      an intercept the slope would be $\dfrac{S_{xy}}{S_{xx}}$ over the centred sums, which is a
      different number; forcing the origin is a modelling claim that a zero predictor implies a zero
      response, and it is the right claim for a hedge ratio. `constants: [0]`.

- [ ] **Step 1: #7 `omitted-variable-bias`.** Statement: regressing a return on both a value signal

      `[-2.5,-1.8,-1.2,0.8,1.5,2.2,3,3.5]`, `delta` range `-1.2..1.2` step `0.2`, `constraint`
      `|delta| >= 0.2`. Derived: `biasTerm` = `b2*delta`, `answer` = `b1 + b2*delta`. **Negatives in
      both `b2` and `delta`** — every printed product parenthesises its negative operand, e.g.
      $${b2}\times(${delta})$ rendered through `fmtNum`. Claim-free: the short regression's
      coefficient is the long one plus the dropped variable's coefficient times the slope of the
      dropped variable on the kept one, $b_s=b_1+b_2g$. Printed chains:
      $${b2}\times${delta}=${biasTerm}$ then $${b1}+${biasTerm}=${answer}$. Sanity check: the bias
      vanishes when either the dropped variable does not belong in the model (`b2` zero) or the two
      signals are uncorrelated (`g` zero) — which is exactly the orthogonal case #12 turns into a
      whole template. `constants: []`.

- [ ] **Step 2: #8 `standard-error-of-a-slope`.** Statement: a regression over `n` observations has
      residual sum of squares `rss` and the predictor's centred sum of squares is `sxx`; what is the
      standard error of the slope? Params as the RESTRUCTURED stub — `sVar` `[4,9,16,25,36,49]`, `n`
      `[12,17,22,27,32,42,52]`, `sxx` `[16,25,36,64,100,144,196,225,256,400]` — with `rss` DERIVED
      as `sVar*(n-2)` and printed in the statement, so the division `rss/(n-2)` is exact and both
      roots are roots of exact literals. Derived (`sVar` is a PARAM, not a derived key — do not
      redeclare it): `rss` = `sVar*(n-2)`, `sSD` = `sqrt(sVar)`, `answer` = `sqrt(sVar)/sqrt(sxx)`
      from exact operands. Claim-free: the residual variance is the residual
      sum of squares over $n-2$ degrees of freedom, two having gone to the intercept and the slope,
      and the slope's standard error is $\dfrac{s}{\sqrt{S_{xx}}}$. Printed chains:
      $\dfrac{${rss}}{${n}-2}=${sVar}$, then $\sqrt{${sVar}}=${sSD}$, then
      $\dfrac{${sSD}}{\sqrt{${sxx}}}=${answer}$ — each root a root of an exact literal, evaluated
      once, labelled thereafter. Sanity check: the precision of a slope is bought with the spread of
      the predictor, not with the number of observations alone — doubling `Sxx` at fixed residual
      variance cuts the standard error by $\sqrt{2}$. `constants: [2]` (the `2` in `n-2`).

- [ ] **Step 3: #9 `regression-to-the-mean-prediction`.** Statement: a desk's annual score has mean
      `mean` and standard deviation `sd` across the firm, **and the same spread in both years**, with
      a year-to-year correlation of `r`; a desk scored `z` standard deviations from the mean last
      year; what score does the fit predict for this year? Params as the stub: `mean`
      `[50,60,70,75,80,100,120]`, `sd` `[4,5,6,8,10,12,15]`, `r` range `0.2..0.9` step `0.1`, `z`
      `[-2.5,-2,-1.5,1.5,2,2.5,3]`. Derived: `dev` = `z*sd`, `shrunk` = `r*z*sd`, `answer` =
      `mean + r*z*sd` from exact operands. **The equal-spread clause is load-bearing** and must be
      in the statement: it is what makes the slope `r` and keeps this template off
      `regression-slope-from-moments`. Claim-free: when the two measurements have the same spread
      the least-squares slope $r\dfrac{s_y}{s_x}$ collapses to $r$, so the prediction is
      $\bar{y}+r(x-\bar{x})$ — the deviation shrunk toward the mean by the correlation. Printed
      chains: $${z}\times${sd}=${dev}$, $${r}\times${dev}=${shrunk}$, $${mean}+${shrunk}=${answer}$.
      Sanity check: prediction moves the desk a fraction `r` of the way out, never the whole way, so
      an extreme year is predicted to be followed by a less extreme one **whatever the desk did** —
      the shrinkage is a property of imperfect correlation, not evidence of mean-reverting skill.
      `constants: []`.

- [ ] **Step 1: #10 `variance-of-a-fitted-value`.** Statement: a fitted line over `n` observations
      has residual standard deviation `sigma` and the predictor's centred sum of squares is `sxx`;
      what is the standard error of the fitted value at a predictor `d` away from its mean? Params
      as the stub: `sigma` `[2,3,4,5,6]`, `n` `[10,16,20,25,40,50]`, `d` `[2,3,4,5,6,8,10]`, `sxx`
      `[100,144,196,225,400,625]`, `constraint` `d*d <= 0.25*sxx`. Derived: `invN` = `1/n`,
      `leverage` = `d*d/sxx`, `h` = `invN + leverage`, `root` = `sqrt(h)`, `answer` = `sigma*sqrt(h)`
      computed from the exact `h`, not from a rounded `root`. Claim-free: a fitted value carries the
      uncertainty of the height of the line and of its tilt, and the two combine as
      $s\sqrt{\dfrac{1}{n}+\dfrac{(x-\bar{x})^{2}}{S_{xx}}}$ — write the fitted value as `f`, never
      `\hat{y}`. Printed chains: $\dfrac{1}{${n}}=${invN}$, $\dfrac{${d}^{2}}{${sxx}}=${leverage}$,
      then **the root over the EXACT literals, not over the two rounded labels** —
      $\sqrt{\dfrac{1}{${n}}+\dfrac{${d}^{2}}{${sxx}}}=${root}$ — then
      $${sigma}\times${root}=${answer}$.
      **Why, and this is not optional:** `leverage` does not terminate on most draws
      (`4/144 = 0.0277…`), so `\sqrt{${invN}+${leverage}}` roots a rounded label and misses `root`
      in the fourth figure. Task 1's spec review measured the identical mistake in this plan's #3
      sketch failing **36 of 290** draws. Root the exact integers in one chain, label the result,
      and never re-root it. Sanity check: at the mean of the predictor the second term
      vanishes and the standard error is just $\dfrac{s}{\sqrt{n}}$ — the line is always most
      precise at the centre of its data and fans out from there, which is why extrapolation is
      dangerous. `constants: [1, 2]`.

- [ ] **Step 2: #11 `slope-after-adding-a-point`.** Statement: a fit over `n` observations has slope
      `b` and centred sum of squares `sxx`; one more observation arrives, sitting `dx` above the
      predictor's mean and `dy` above the response's mean; what is the slope after refitting? Params
      as the stub: `n` `[9,11,14,19,24]`, `sxx` `[100,120,150,200,240,300]`, `b` range `0.4..2.4`
      step `0.2`, `dx` `[4,5,6,8,10,12]`, `dy` `[-12,-8,-6,6,8,12,16,20]`. Derived: `w` = `n/(n+1)`,
      `sxy` = `b*sxx`, `numer` = `sxy + w*dx*dy`, `denom` = `sxx + w*dx*dx`, `answer` =
      `numer/denom` — exactly rational, computed from exact operands throughout. **`dy` is often
      negative**: every printed product parenthesises it. Claim-free: adding a point moves both
      centred sums, and because the means themselves shift the new point contributes
      $\dfrac{n}{n+1}$ of its raw deviation to each — so the slope becomes
      $\dfrac{S_{xy}+wd_xd_y}{S_{xx}+wd_x^{2}}$. Printed chains: `w` as one chain, then
      $${b}\times${sxx}=${sxy}$, then numerator and denominator each as one chain, then the final
      quotient. Sanity check: a point far out in the predictor pulls the line hardest — the same
      `dy` at twice the `dx` moves the slope by more, which is leverage, and it is why a single
      outlier in the predictor can rewrite a fit. **Asked as the new slope, never as the change.**
      `constants: [1, 2]`.

- [ ] **Step 3: #12 `prediction-with-orthogonal-regressors`.** Statement: two signals are
      **uncorrelated in the sample**; regressing the return on each alone gives slopes `b1` and `b2`,
      and the return averaged `ybar`; what does the two-signal fit predict for a day on which the
      signals sit `d1` and `d2` from their own means? Params as the stub: `ybar`
      `[40,55,70,85,100,120]`, `b1` range `0.5..2.5` step `0.5`, `b2` `[-3,-2,-1.5,1.5,2,3,4]`, `d1`
      `[-6,-4,-2,3,5,8]`, `d2` `[-5,-3,2,4,6,9]`. Derived: `t1` = `b1*d1`, `t2` = `b2*d2`, `answer`
      = `ybar + b1*d1 + b2*d2`. **Negatives everywhere** — `b2`, `d1` and `d2` all draw negative;
      parenthesise every negative operand. Claim-free: when two predictors are uncorrelated in
      sample, each one's multiple-regression coefficient equals its simple-regression slope, because
      neither carries any of the other's information; the fit is then just the two separate
      adjustments added to the mean. Printed chains: $${b1}\times${d1}=${t1}$,
      $${b2}\times${d2}=${t2}$, then $${ybar}+${t1}+${t2}=${answer}$. Sanity check: this is the case
      where #7's omitted-variable bias is exactly zero — dropping either signal would leave the
      other's coefficient untouched. With correlated signals none of this holds and the simple
      slopes are not the multiple ones. `constants: []`.

- [ ] **Step 4: Claims** — **#10**: answer recomputed as `sigma*sqrt(1/n + d*d/sxx)`; `h ===
